# The Block (hawioyugi.com) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the old portfolio in `site/` with the approved pixel "block" page, rebuilt cleanly from the example in `spike-block/`, and get it to a Vercel preview for Hawi to test.

**Architecture:** One Next.js page. The server renders a plain-text version of all content and reads the doom scroll headlines; a thin client component mounts a vanilla three.js "scene app" (`mountBlock`) on top. The scene app is the example's `main.js` split into modules with one job each that share a single `world` object; cards, chat and captions stay as plain DOM driven by the scene loop, because they are placed and animated per frame. All wording lives in one typed content file.

**Tech Stack:** Next.js 16.2.7 (App Router, no Cache Components), React 19, TypeScript for app code, plain JavaScript modules for the scene (`allowJs` is on), three.js 0.187, `next/font/google` (Pixelify Sans, IBM Plex Mono), Vitest, playwright-core for the browser checks.

**Spec:** `docs/superpowers/specs/2026-11-19-the-block-design.md`. The visual and behavioural reference is `spike-block/` (`main.js`, 1,861 lines, and `index.html`). Serve it with `cd spike-block && python3 -m http.server 8767`.

## Review Focus

1. **The scene cannot start** (no WebGL, or the context is lost): the visitor sees the text version with every link working, not a blank cream page.
2. **The blog feed is down, slow or malformed:** the page still builds and renders; the newsstand card shows its line and button with no rows.
3. **Motion turned off in system settings:** no shots, no flying ball, no typing, no bounce; the chat still opens at the end of the scroll and every card still opens.
4. **Keyboard only:** every card and the chat can be opened, used and closed without a mouse, and focus is never trapped.
5. **Arriving or changing mid-way:** loading part-way down, resizing, or rotating a phone during a shot or with a card or the chat open leaves nothing stuck (no hidden ball, no card off screen, no chat without its close button).

Each line has a check in `site/scripts/check.mjs` or a unit test, added in these tasks: 1, 3 and 4 in Task 7; 2 in Task 2 (parser and fallback) and Task 4 (newsstand with no headlines); 5 in Task 3 (loaded part-way), Task 4 (resize), Task 5 (rotate with a card) and Task 6 (rotate with the chat, scroll back up).

**The shared `world` object** (created in `scene/index.js`, passed to every `create*` function, which reads what it needs and adds what it owns):

```js
world = {
  THREE, root, stage,            // root: the mount element; stage: the div the canvas lives in
  content, headlines,            // from content/site.ts and lib/doomscroll.ts
  reduced, touch, debug,         // booleans: prefers-reduced-motion, pointer: coarse, ?debug in the URL
  scene, camera, renderer,       // pixels.js
  HOOP, ball, net,               // court.js
  guy, st, mv, sh,               // player.js: figure group, dribble state, movement state, shot state
  view,                          // camera.js: { p, pT, c, cT, k, kT, f, fT, fH, fB, aspect, startHalfH, endHalfH }
  pops,                          // block.js: array of thing groups; group.userData is the card data
  made,                          // captions.js: boolean, true once the opening shot has dropped
  cards, chat,                   // cards.js / chat.js: the small APIs listed in their tasks
}
```
